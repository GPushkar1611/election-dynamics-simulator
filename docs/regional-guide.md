# Step 4: Regional elections and social spillover

Implemented in `election_sim/region.py`; tests in `tests/test_region.py`.
All inputs and outputs describe synthetic scenarios.

## Run Region 1

From the project root:

```powershell
python -m election_sim.region_cli --config configs/baseline.json --constituencies 1 2 3 4 5 6 7 --spillover 0.1 --seed 42 --sweep --output results/region1_seed42
```

This runs 21,000 voters for 30 days, saves the chosen spillover run and also
writes a paired sweep over 0, 0.05, 0.1 and 0.2. Choose a fresh output directory.
The sweep is a single-seed mechanics demonstration; 30-seed uncertainty studies
belong to step 5.

To run local candidate agents for every party in every selected constituency:

```powershell
python -m election_sim.region_cli --config configs/agents.json --party-scenario configs/region1_parties.json --constituencies 1 2 3 4 5 6 7 --spillover 0.1 --seed 42 --record-history --output results/region1_agents_seed42
```

Party budgets and reach apply separately in each constituency. The example
allocates each local candidate a 3,000-contact budget; there is no shared
party-wide purse. `lambda_campaign` must be positive when campaigns/agents
are supplied.

## Python interface

```python
from election_sim import SimulationConfig, simulate_region, spillover_sweep

result = simulate_region(
    SimulationConfig(), [1, 2, 3, 4, 5, 6, 7], seed=42, spillover=0.1,
    data_dir="data/synthetic_election_dataset", record_history=True,
)
print(result.seats)
print(result.constituencies[1].turnout)
result.save("results/my_region_run")
```

`data_dir` defaults to the dataset folder under the package's repository root.
Alternatively supply `data` with voters, candidates, social_network and events
DataFrames. The CSV route validates the complete dataset before selecting
voters. `load_region(data_dir, days=30, events_file=None)` returns those validated
full tables for reuse across runs. Direct DataFrame callers must supply valid
schema and geography; selected IDs/ballots/graph and model values are checked
again by the simulation.

## Mechanics and controls

- Select unique constituency IDs from one region. Unknown IDs and mixed regions
  are rejected. Candidates require party_id for seat aggregation.
- Every day, all constituency engines pause at the social update. The regional
  runner assembles their current opinions in one canonical voter array and
  computes a single synchronous bounded-confidence update using np.bincount.
  Each constituency then continues its existing campaign, news, support and
  history workflow. This uses the same daily engine as single-constituency runs.
- Internal social ties keep their original weights. Cross-constituency ties
  between selected voters have raw weight multiplied by spillover, in [0, 1],
  before sender influence and incoming-weight normalization. Ties to voters
  outside the selected set are excluded and counted in metadata.
- Spillover 0 removes cross ties exactly. Same-seed results match standalone
  constituency runs, including agents, news, mobilization and final ballots.
- Scaling weights changes relative neighbour influence. If a voter has only
  cross-constituency incoming neighbours, normalization cancels a common
  nonzero scale; spillover is not an absolute movement-rate multiplier.
- Voters only support and vote for candidates on their local ballot. Polls,
  budgets, communities, targeting ranks, direct campaigns, news processing and
  smear claims remain local. Social opinions cross boundaries; smear beliefs
  are not transferred between different constituencies' candidate claims.
- Local/regional/state event scopes are preserved. Out-of-ballot fact-checks
  have no local claim to correct and are skipped. Other candidate-linked news
  keeps the existing foreign-candidate neutral-shock semantics. Random news is
  generated by each local news agent; the same master seed preserves standalone
  controls and can correlate random schedules across constituencies.
- Every local engine uses the supplied master seed and existing purpose-specific
  streams. Changing constituency order or input row order does not change results.
  The streams are reproducible common draws, not independent constituency samples.

## Party mapping

`party_campaigns` is a list of CampaignAction dictionaries using party_id instead
of candidate_id, and target_party_id instead of target_candidate_id for smears.
Each action is copied onto each selected constituency's candidate, with a
constituency suffix added to action_id. Missing or ambiguous party mappings fail.

`party_agents` is a list of CandidateAgent dictionaries using party_id instead
of candidate_id. Local polls and budgets are isolated. You can instead supply
normal candidate-specific `campaign_actions` and `agents`; candidates must be
selected and smear targets must be on the same local ballot. Duplicate local
agents/actions are rejected by the existing engine.

## Outputs

- `candidate_results.csv`: constituency, candidate, party, votes, shares, support.
- `turnout.csv`: one row per constituency, including winner IDs and accounting.
- `seats.csv`: seats_won and tied_constituencies per party. A tied seat or
  zero-turnout constituency awards no seat; unresolved IDs appear in the manifest.
- `daily_summary.csv` and `daily_support.csv`: local daily metrics with constituency IDs.
  Local eligible_edges counts internal edges; it is not a regional edge count.
- `manifest.json`: region, selected constituencies, config, seed, spillover,
  original/effective/boundary edge counts and input graph fingerprint.
- `C01/`, `C02/`, etc.: normal RunResult outputs, manifests, diagnostics and
  optional full history, retaining each local candidate axis.
- With history enabled, `region_history.npz` contains all selected voter IDs,
  constituency IDs and opinions [days+1, voters] in canonical ID order.
- With --sweep, `spillover_sweep.csv` contains candidate results for all four
  coefficients using matching seeds.

```powershell
python -m unittest discover -s tests -p "test_*.py"
python -m unittest discover -s constituency_loader -p "test_*.py"
```

Regional checks cover exact zero-spillover controls, synchronous weighted
cross influence, direction/confidence, row-order invariance, history alignment,
party mapping, local polls/budgets, event geography, vote/seat accounting,
ties/zero turnout, saving, sweep coverage and invalid inputs.
